## Findings (all fixed)

1. **`StaffPickerList` stale-selection effect raced the async policy load.**
   The "clear a now-cart-full selection" effect ran with
   `maxConcurrentPerStaff` still at its `useState(1)` default before
   `getStaffPickerOptions` resolved, so at a branch with capacity ≥ 2 it
   wrongly reset a valid specific-staff pick when the user went Back to edit a
   bundled sub-booking. **Fix:** gate the effect on `!isLoading` (and add
   `isLoading` to its deps) so it only runs once the real per-branch value has
   loaded. `StaffPickerList.tsx`.

2. **`getStaffPickerOptions` serialized two independent DB round-trips.**
   `await listAvailableStaff(...)` then `await resolveEffectivePolicy(...)`
   added a full round-trip of latency to every Staff Picker open on a
   customer-facing endpoint. **Fix:** `Promise.all([...])`. Server specs still
   green (the FIFO `.from()` mock order is unchanged). `staffPicker.service.ts`.

3. **Care-instructions banner offered no jump for a hidden _dateless_ partial row.**
   A half-filled row created in uniform mode (`stay_date = null`) and then
   hidden by switching to a specific night tab left a blocking banner with no
   "Go to…" button (the button was gated on `stayDate !== null`). **Fix:** the
   button now shows whenever the row's scope differs from the active tab and
   reads "Go to Default (all nights)" for a dateless row (jumping to the
   Default tab). `CustomerBookingFlowPage.tsx`.
