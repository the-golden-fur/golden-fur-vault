## Verdict: APPROVE WITH NITS

The change does three things, as derived from the diff: (1) `SettingsPage`
drops its VSCode-style modal shell (backdrop, `modalPanel`/
`modalPanelFullscreen`, `role="dialog"`/`aria-modal`, the `isFullscreen`
toggle state) and instead renders as a plain full-bleed page inside
`AppShell`'s existing `<main>` content area — this also removes a
pre-existing invalid nested-`<main>`-landmark issue rather than introducing
one; (2) a new `SidebarCollapseContext`/`useSidebarCollapse` lets
`SettingsPage` force-collapse the real dashboard `Sidebar` (now owned by
`AppShell`) on mount and restore whatever the user had before, on unmount;
(3) every `ConfigTileConfig` gains a required `icon: LucideIcon`, threaded
through `DashboardTile`'s new optional `icon` prop and rendered in both the
Config tile grid and the Settings sidebar's Config sub-list. I traced the
hook-ordering, ref-capture-of-prior-state, and route-nesting (both
`StaffAuthGuard` and `CustomerAuthGuard` render `AppShell`, so
`SettingsPage` always sits inside a real `SidebarCollapseContext.Provider`,
never the inert default) and found no correctness bug. All findings below
are non-blocking cleanliness/consistency/test-gap items; safe to proceed.

## Non-blocking findings

### N1. New context value isn't memoized, unlike the sibling `ThemeProvider` — `client/src/shared/components/AppShell/AppShell.tsx:82-83`

`<SidebarCollapseContext.Provider value={{ collapsed, setCollapsed: setCollapsedPersist }}>` creates a fresh object every render of `AppShell`. `ThemeProvider.tsx` (the existing sibling provider) wraps its own context value in `useMemo` specifically to avoid this. Today the only consumer is `SettingsPage`, so the cost is low, but it will re-render on every unrelated `AppShell` render (e.g. a `notificationBell`/`identity` prop change) once more consumers show up. Wrap in `useMemo([collapsed, setCollapsedPersist])`.

### N2. `SidebarCollapseProvider/` directory holds no Provider component — `client/src/shared/providers/SidebarCollapseProvider/sidebarCollapseContext.ts`

Every other folder under `shared/providers/` (`ThemeProvider/`, `ToastProvider/`) contains both a `<Name>Provider.tsx` component (that owns the state and renders `<XContext.Provider>`) and a `xContext.ts` file. This new folder contains only the context file — the actual `<SidebarCollapseContext.Provider>` is instantiated inline inside `AppShell.tsx` instead, since `AppShell` already owns the `collapsed` state. That's a reasonable design choice, but the folder name now overpromises (there's no `SidebarCollapseProvider.tsx` to find). Either rename the folder (e.g. `shared/context/sidebarCollapseContext.ts`) or extract a real thin `SidebarCollapseProvider.tsx` wrapper to match the established convention.

### N3. Formatting: JSX body of `.map()` isn't indented under `return (` — `client/src/pages/SettingsPage/SettingsPage.tsx:563-608`

The `orderedConfigTiles.map((tile, tileIndex) => { const TileIcon = ...; return ( <div key={tile.to}> ... ); })` conversion from an implicit-return arrow to a block body left the returned JSX (`<div key={tile.to}>` through `</div>`) at the _same_ indent level as `const TileIcon =` / `return (`, rather than one level deeper as Prettier normally produces for a parenthesized return. This is very likely to fail `npm run format:check` in CI (this is a genuine indentation deviation the diff introduced, not the pre-existing Windows CRLF noise on untouched files). Worth an actual Prettier pass before opening the PR.

### N4. Stale "Fullscreen toggle" reference in a doc comment — `client/src/pages/SettingsPage/configTiles.config.ts:31-35`

The `Component` field's doc comment still says "...and what the Fullscreen toggle navigates to instead of just resizing the panel, once one of these is active." The "resize the panel" behavior no longer exists at all (the whole `isFullscreen` state was removed), and the control is now labeled "Open as a full page" in the UI/tests, not "Fullscreen toggle." Minor doc-staleness, worth a follow-up wording pass.

## Test coverage

- `SettingsPage.spec.ts` was updated correctly for the removed dialog/fullscreen-toggle assertions and the new full-bleed rendering, and its mocked `CONFIG_TILES`/`SYSTEM_CONFIG_TILE` fixtures were given an `icon`. However `renderPage()` renders `<SettingsPage>` directly under `MemoryRouter`/`AuthContext`, with **no `AppShell` and no `SidebarCollapseContext.Provider` ancestor at all**. That means every existing `SettingsPage.spec.ts` test exercises `useSidebarCollapse()` against the context's _default_ stub value (`{ collapsed: false, setCollapsed: () => undefined }`), so the actual new behavior this PR adds — force-collapsing the real dashboard sidebar on mount and restoring the prior value on unmount — has **zero test coverage**. Neither `AppShell.spec.ts` (also unmodified in this diff) nor any new spec asserts that a child calling `setCollapsed(true)` actually flips `AppShell`'s own `collapsed` state, or that unmounting restores the pre-existing value. A human should add at least one test wrapping a probe component in `AppShell` to cover this round-trip.
- `DashboardTile.spec.ts` and `ConfigTab.spec.ts` were **not updated** for the new `icon` prop — `ConfigTab.spec.ts` does exercise the real (non-mocked) `CONFIG_TILES`, so it does implicitly render an icon on every tile without crashing, but nothing asserts the icon actually renders (e.g. via `container.querySelector('svg')` or similar). Low-value gap given this is a purely decorative prop, but worth noting.
- Suites were not run as part of this review (that is `ci-verifier`'s job); the Prettier issue at N3 and the coverage gaps above should be confirmed/closed before the PR is opened.
