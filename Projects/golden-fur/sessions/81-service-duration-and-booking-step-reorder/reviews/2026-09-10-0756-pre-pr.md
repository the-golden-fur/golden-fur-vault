## Findings — fixed

### 1. Accumulated `slotDurationMinutes` outside the availability endpoint's 15–1440 range 400s the Date & Time step

`CustomerBookingFlowPage.tsx`. Once Services precede Date & Time, the value
passed to `SlotPicker` is the sum of every selected service/package duration.
`availabilityQueryValidator` accepts `slot_duration_minutes` only in
`[15, 1440]` (`.strict()`). A single quick service an admin set to 1–14
minutes, or a pile summing past 1440, would 400 the whole step (previously the
fixed `DEFAULT_DURATION_MINUTES` stand-in was always valid).

Fix: the call site clamps to `Math.min(1440, Math.max(15, slotDurationMinutes))`
before it reaches `SlotPicker`. The submitted window (`finalScheduledEnd`)
still uses the true sum.

### 2. A slot picked against a shorter window survived a Back-and-add-service

`CustomerBookingFlowPage.tsx`. `toggleServiceSelect` / `togglePackageSelect`
had stopped clearing `selectedSlot` (the "#22 follow-up" removed it _because_
items then came after Date & Time). With the order reverted, going Back to
Services and adding an item grew `finalScheduledEnd` without dropping the slot,
so the wizard could reach Confirm with a window that overran staff availability
— the server then rejected it with an opaque error at the last step.

Fix: new `resetSlotForItemChange()` helper (clears slot + staff + cage picker
state, no-op until a slot exists so building the list on the way _in_ costs
nothing), called at the top of both toggles; stale "#22 follow-up" comments
replaced. New regression test: "going Back from Date & Time and changing the
service set drops the already-picked slot".

## Findings — accepted / documented, not fixed

### 3. Over-1440 pile: capacity checked against a shorter window than submitted

Same clamp as finding 1: a booking whose services sum past 1440 minutes is
availability/staff-checked against a 1440-minute window while `finalScheduledEnd`
runs longer, so an overflow could double-book. Not a real grooming/vet scenario
(>24h of same-day services on one pet); Hotel's length rides the nights
multiplier, not this sum. Left clamped with an inline comment; noted in
`testing/testing.md` open items.

### 4. `resetSlotForItemChange()` also fires on a net-zero toggle

Toggling a service off then on again after a slot is picked still clears the
slot/staff/cage even though the window length is unchanged. Minor: the user
_did_ touch the service list after choosing a time, so re-confirming the time
is defensible, and the `if (!selectedSlot) return` guard keeps the common
forward path free. Left as-is.

### 5. Historical seed migration edited in place

`20260715034_m13_seed_maintenance_data.sql` gets the `duration_minutes` values
inline (matching the user's "update all affected seed files"), even though on a
provisioned DB the values actually land via the new `20260910183` backfill (the
insert is `ON CONFLICT DO NOTHING` and never re-runs). `supabase db push` skips
already-applied migrations so it won't fail, but `migration list` / `repair`
could show a checksum divergence. Mitigated with a comment in `20260715034`
pointing at the backfill and stating the two files carry the same numbers.
